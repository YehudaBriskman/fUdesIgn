# Citations and sources: next to the claim, one step from the passage

> Put a numbered citation marker right after the claim it supports. On hover, focus or tap it previews the source's title, domain, date and the exact supporting passage, and it opens that passage, not just the page. List every source below the answer. Never show a citation for a source the system did not actually retrieve.

**Category:** Chat and conversation · **Applies to:** grounded chat answers, AI search, research and "deep research" reports, summaries of documents, answers over a user's own files · **Priority:** must

## When to use / when not
- Any answer built from retrieved material: web search, a knowledge base, the user's files, a database query.
- For answers with no retrieval (brainstorming, rewriting the user's own text), show no citations and say nothing about sources. Don't invent a "Sources" section to look trustworthy.
- If retrieval ran but nothing supports a claim, that claim gets the "unsourced" warning from `aifound-uncertainty-and-disclaimers.md`, not a citation to the nearest document.
- Rendering of links inside the answer body (sanitising, `rel` values) is covered in `aichat-markdown-code-tables.md`.

## Rules (do)
- **Marker next to the claim.** Place a superscript-style marker (`[1]`, or a compact chip with the domain) directly after the sentence or clause it supports, never only at the end of a paragraph that holds several claims. NN/g recommends putting each citation next to its claim and linking to the exact passage.
- **One marker per distinct source**, numbered in order of first use across the whole answer. The same source keeps the same number when reused. At most 3 markers on one sentence; above that, cite the 3 strongest and put the rest in the list.
- **Preview on hover, focus and tap.** The preview shows: title, domain (and favicon), publication or last-modified date, and the passage that supports the claim, about 1–3 sentences with the matched words highlighted. Open after the 500 ms interest delay on hover, immediately on focus or tap.
- **Deep-link to the passage.** For web pages use a text fragment (`#:~:text=`) or an anchor; for files use page and line or cell references; for your own records use the record URL plus the field. NN/g found that links which make users hunt for the passage discourage checking. Check the fragment resolves before showing it; fall back to the page URL with the quoted passage in the preview.
- **Descriptive labels.** The list shows the title and domain, not "Source 1" or a bare URL. NN/g's explainable-AI study prefers descriptive labels over "Source".
- **Only retrieved sources, only supporting ones.** A citation is generated from the retrieval record (document ID, offsets), never from text the model writes. Drop any citation whose passage does not contain support for the claim (an entailment or string-overlap check). Never render a URL the model produced from memory as a source.
- **Dead links are bugs.** Check status before showing a source (or at retrieval time) and mark unreachable ones "Link unavailable, passage saved" with the cached passage. NN/g lists 404 source links as a bad example.
- **Sources list under the answer**: numbered to match the markers, collapsed to the first 3–5 with "Show all N sources", each with title, domain, date. Also list sources retrieved but not cited under a separate "Also searched" disclosure if users need to judge coverage; never mix them with cited ones.
- **Show the freshness and type of each source** (news, docs, forum, your files). Forum and user-generated content gets a type label: Google's May 2024 AI Overviews post-mortem traced errors to satire and forum posts treated as fact.
- **Make checking cheap.** Offer a follow-up chip "Show where this comes from" and, for a claim the user selects, "Which source supports this?". NN/g counts about 6 steps to check one answer; aim for 1 (hover) or 2 (open the passage).

## Anti-patterns (don't)
- A "Sources" block at the end with no inline markers, so no claim maps to any source.
- Markers that point to the homepage or a search results page.
- Citations generated by the model as text ("(Smith, 2021)") with no retrieval record behind them.
- Showing 15 source favicons above the answer as decoration.
- A citation to a source that says something different from the claim.
- Hover-only previews that never open on keyboard focus or touch.

## Bad references
- Mata v. Avianca, 22-cv-1461 (S.D.N.Y. 22 June 2023, Castel, J.) ([opinion and order on sanctions](https://storage.courtlistener.com/recap/gov.uscourts.nysd.575368/gov.uscourts.nysd.575368.54.0.pdf)): ChatGPT produced six non-existent decisions that the lawyers cited as real; the court imposed one $5,000 penalty jointly and severally on the two lawyers and their firm. Citations not backed by retrieval are indistinguishable from real ones in plain text.
- Footnoted chat answers in NN/g's diary study ([Information foraging with generative AI](https://www.nngroup.com/articles/generative-ai-diary/)): footnotes existed but checking them was tedious, and participants verified only 22.4% of conversations.
- Google AI Overviews, May 2024 ([post-mortem](https://blog.google/products/search/ai-overviews-update-may-2024/)): answers quoted satire and forum jokes; nothing in the UI showed the source type.

## Accessibility
- Each marker is a link or button with an accessible name that says what it is: "Source 2: Annual report 2025, example.com". The visible "[2]" alone is not a name.
- The preview is a non-modal popover attached with `aria-describedby` or `popovertarget`; it opens on focus and closes on Esc without moving focus. Content in it is reachable by keyboard (Tab into its link).
- Markers are at least 24×24 CSS px as a target (WCAG 2.5.8), even if the glyph is smaller: pad the hit area.
- The sources list is a real `<ol>` whose item numbers match the markers.
- Highlighted words in the passage use `<mark>`, which screen readers can announce, plus a background, never only colour.

## Motion / interaction (if relevant)
- Preview opens with a 150 ms fade (`--motion-dur-short`), no slide under reduced motion.
- Clicking a marker while the source list is on screen scrolls to and briefly highlights the list item (240 ms background fade). Scroll smoothly only without a reduced-motion preference.

## Implementation sketch
```ts
// Citations come from the retrieval record, never from model-written text.
type Passage = { docId: string; start: number; end: number; text: string };
type Source = { id: string; title: string; url: string; domain: string; date: string | null; kind: 'web' | 'file' | 'record' | 'forum' };
type Citation = { n: number; source: Source; passage: Passage };

// Build a deep link to the passage with a text fragment; the caller checks it resolves.
export function deepLink(src: Source, p: Passage): string {
  if (src.kind !== 'web') return src.url;
  const words = p.text.trim().split(/\s+/);
  const quote = words.length > 8 ? `${words.slice(0, 4).join(' ')},${words.slice(-4).join(' ')}` : words.join(' ');
  return `${src.url.split('#')[0]}#:~:text=${quote.split(',').map(encodeURIComponent).join(',')}`;
}

// Number sources by first use; reuse the number when a source repeats; drop unsupported ones.
export function numberCitations(
  claims: { sourceId: string; passage: Passage; supported: boolean }[],
  sources: Map<string, Source>,
): Citation[] {
  const order = new Map<string, number>();
  const out: Citation[] = [];
  for (const c of claims) {
    const source = sources.get(c.sourceId);
    if (!source || !c.supported) continue;          // never cite unretrieved or non-supporting sources
    const n = order.get(source.id) ?? order.size + 1;
    order.set(source.id, n);
    out.push({ n, source, passage: c.passage });
  }
  return out;
}
```

## Checklist
- [ ] Every grounded claim has a marker directly after it; ≤ 3 per sentence.
- [ ] Markers map to retrieval records; no model-written citations; unsupported ones dropped.
- [ ] Preview opens on hover, focus and tap with title, domain, date and the supporting passage.
- [ ] Links land on the passage (text fragment, page/line, record field), and dead links are marked.
- [ ] A numbered sources list matches the markers, with descriptive titles.
- [ ] Each marker has a descriptive accessible name and a 24 px target.
