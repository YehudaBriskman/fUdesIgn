# Accessibility statements

> Publish one honest statement, linked from every page's footer (and the app's settings or help), that names the standard and level (WCAG 2.2 AA), the conformance status, the known gaps with dates or alternatives, how it was evaluated and when, and a working contact route with a response time; never claim "fully compliant" from an automated scan.

**Category:** Law and statements · **Applies to:** websites, web apps, mobile apps, documents portals; EU public sector, EAA services, Israeli services, procurement · **Priority:** should

## When to use / when not
- **Required** for EU public-sector sites and apps (Web Accessibility Directive, model statement in Commission Implementing Decision (EU) 2018/1523), effectively required for EAA services (Annex V service information), and required in Israel by regulation 35ה (`alaw-legal-landscape.md`).
- **Recommended everywhere else:** it gives users a route to report barriers and shows what you know.
- **Not** a substitute for fixing issues, and not a place for marketing language.

## Rules (do)
- **Placement:** a link labelled "Accessibility" (Hebrew: "הצהרת נגישות") in the global footer of every page and in the app's settings or help; the page itself is accessible and reachable without logging in.
- **Contents (combining the W3C generator, the EU model statement and Israel reg. 35ה):**
  1. Commitment and scope: which sites, apps and domains it covers.
  2. Standard and level: "WCAG 2.2 Level AA" (and, where relevant, "EN 301 549 V3.2.1" or "IS 5568 level AA").
  3. Conformance status, using W3C terms: fully conforms, partially conforms, or does not conform.
  4. Known limitations: each with the affected content, the reason (for example third-party map, legacy PDFs), the workaround or alternative, and a fix date if one exists. Exemptions claimed (EAA Art. 14 burden, Israeli reg. 35ו exemptions) are named here.
  5. Accessibility features worth knowing (skip link, keyboard shortcuts and how to turn them off, text alternatives).
  6. Compatibility: browsers and assistive technologies tested (`atest-screen-reader-cheatsheets.md`).
  7. Evaluation method and date: self-evaluation or external audit, automated plus manual, the date of the last review.
  8. Feedback and contact: email, phone and form; for Israel, the accessibility coordinator's name and contact where the law requires one; expected response time.
  9. Enforcement or complaints route: the national body (for example the EU member-state enforcement body, or Israel's Commission for Equal Rights of Persons with Disabilities).
  10. Date the statement was prepared and last updated.
- **Response commitment:** acknowledge reports within 2 working days and fix or provide an alternative within the legal limit (60 days after notice in Israel, reg. 35א(d)).
- **Keep it current:** update on every audit and at least yearly; a statement older than a year signals neglect.
- **Plain language:** short sentences, no jargon beyond the standard's name.

## Anti-patterns (don't)
- "This website is 100% accessible and compliant" with no standard, level or date.
- Statements generated by an overlay vendor that list the overlay's toolbar as the accessibility feature.
- No contact route, or a contact form that is itself inaccessible (CAPTCHA, unlabeled fields).
- Hiding the link inside a legal page or only in the cookie banner.
- Listing WCAG 2.0 for a product built and audited against 2.2.

## Bad references
- Overlay-generated statements claiming conformance because a widget is installed (see `aref-anti-patterns.md` and i18n-rtl `iref-hebrew-sites-and-israeli-accessibility.md`).

## Accessibility
- The statement page meets the same standard it claims: headings, lists, links with clear names, a contact form with labels and no CAPTCHA puzzle.

## Implementation sketch
A typed statement model rendered to the page, so missing fields fail type-checking rather than ship.
```ts
type Status = 'fully conforms' | 'partially conforms' | 'does not conform'

interface Limitation { content: string; reason: string; alternative: string; fixBy?: string }
interface Contact { email: string; phone?: string; formUrl?: string; coordinator?: string; responseDays: number }

export interface AccessibilityStatement {
  scope: readonly string[]
  standard: 'WCAG 2.2 AA'
  alsoMeets?: readonly ('EN 301 549 V3.2.1' | 'EN 301 549 V4.1.1' | 'IS 5568 AA')[]
  status: Status
  limitations: readonly Limitation[]
  tested: readonly string[]          // e.g. 'NVDA 2026.3 + Firefox 145'
  method: 'self-evaluation' | 'external audit'
  lastReviewed: string               // ISO date
  contact: Contact
  enforcement: string
}

export function isStale(s: AccessibilityStatement, now: Date = new Date()): boolean {
  const ageDays = (now.getTime() - new Date(s.lastReviewed).getTime()) / 86_400_000
  return ageDays > 365
}
```

## Checklist
- [ ] Linked from every page's footer and from the app.
- [ ] Names standard, level and conformance status.
- [ ] Lists known limitations with alternatives and dates; exemptions disclosed.
- [ ] States evaluation method and date of last review.
- [ ] Gives a working contact route, coordinator where required, and response time.
- [ ] Names the complaints or enforcement route.
- [ ] Reviewed within the last 12 months.
